# Проверка наивного агента баг-ассистента

## Реализация

Агент запускается через CLI:

python -m app.services.agent_naive "<задача>" --trace

Используется Chat Completions с моделью gpt-5.4-mini.
Цикл ограничен max_steps=6. На каждой итерации выполняется один
вызов Chat Completions. Параллельные вызовы инструментов отключены.

Доступны три инструмента:
- search_knowledge_base — поиск по действующей базе багов;
- get_current_time — получение времени через ZoneInfo;
- send_telegram_message — заглушка отправки, печатающая текст в консоль.

DISPATCH содержит явный словарь разрешённых функций.
Неизвестное имя инструмента возвращается модели как строка-ошибка.
Реальные запросы к Telegram API не выполняются.

run_agent возвращает answer, steps, trace и error при аварийной
остановке или достижении лимита.

Trace содержит номер шага, имя инструмента, исходные JSON-аргументы,
первые 200 символов результата, количество входных и выходных токенов
Chat Completions и длительность шага.

duration_ms включает вызов модели и выполнение инструмента.
Токены эмбеддингов в показатели Chat Completions не входят.
Финальный ответ записывается отдельным шагом с tool_name=null.

## Внесённые изменения

1. Установлены зависимости трассировки, необходимые для импорта RAG.
2. Добавлено подробное логирование исключений инструментов.
3. Добавлена обработка пустого финального ответа с error=empty_answer.
4. Общий промпт баг-ассистента заменён отдельным агентным промптом.
5. Уточнены правила поиска, сопоставления и сообщения
   о недоступных действиях.
6. Добавлена проверка ответа «Подходящих багов не найдено»
   без предшествующего вызова поиска: error=search_not_performed.
   Эта проверка контролирует наличие вызова, но не доказывает
   успешность поиска или правильность сопоставления.
7. Реализации инструментов, явный DISPATCH и JSON Schema TOOLS
   размещены в app/services/agent_naive_tools.py.
8. Промпт вынесен в app/services/agent_naive_prompt.py.
9. Для устранения потери полей добавлена загрузка полной карточки
   выбранного бага из локального хранилища документов.

## Проверка сопоставления с исходными карточками

### Баг 112

Карточка описывает сообщение «Чек аннулирован», после которого
чек успешно фискализируется и печатается.

Это не подтверждает соответствие обращению о зависании перед печатью.
В длинном сценарии агент ошибочно отправил этот баг как релевантный.

В исходной карточке заполнены статус «Создана» и тема.
Агент вывел их как отсутствующие. Полный текст фрагмента,
полученного моделью в том прогоне, отдельно не проверен.

### Баг 142

Карточка описывает некорректную сумму списания за подписку на КС.

Она соответствует обращению о лишней оплате подписки.
Одного упоминания списания при ошибке кассы недостаточно,
чтобы считать эту карточку релевантной.

Ошибка такого сопоставления сохранилась в 09-unknown-tool.log.

## Причина отсутствия временного решения

Фрагменты карточки 142 прочитаны непосредственно из Qdrant
без запросов к модели и эмбеддингам.

Результат сохранён в 142-chunks.txt:
- первый фрагмент содержит название, статус и описание;
- второй фрагмент содержит временное решение.

При возврате только первого фрагмента временное решение
модели недоступно. Данные в коллекции не потеряны.

Обрезка tool_result до 200 символов применяется только к trace.
Она не ограничивает текст, возвращаемый инструментом модели.

## Расширение контекста до полной карточки

search_knowledge_base выбирает лучший поисковый фрагмент,
затем загружает полную карточку соответствующего бага
из существующего docstore через _read_documents().

Проверяется соответствие версии документа данным индекса.
Переиндексация не выполняется. Для загрузки карточки не требуется
дополнительный вызов модели или API эмбеддингов.

Это осознанное расширение исходного требования:
вместо «top-1 фрагмент» возвращается «полная карточка,
выбранная по top-1 фрагменту».

Сигнатура инструмента, allowlist, цикл и формат trace сохранены.
Расширение контекста само по себе не гарантирует
правильного сопоставления обращения с багом.

## Проверка после загрузки полной карточки

| Сценарий | Шаги | Фактический результат | Лог |
|---|---:|---|---|
| Поиск и отправка по подписке | 3 | Найден баг 142, переданы название, статус «В работе» и временное решение из исходной карточки. Выполнена отправка-заглушка, получен непустой финальный ответ. | 10-full-card.log |

Последовательность:
1. Поиск и получение полной карточки.
2. Отправка-заглушка в чат 12345.
3. Финальный ответ: «Отправка в чат 12345 выполнена в учебном режиме».

Временное решение:
«Отмените подписку на КС и дождитесь даты следующего списания.
В дату списания оплатите и активируйте».

Окончание исходного текста не дополнено выдуманными сведениями.
В этом прогоне проблема недоступности временного решения устранена.

## Проверки без внешних запросов

Команда:

python -m scripts.check_naive_agent

Подтверждено:
- искусственно заданный неизвестный get_user_balance возвращён модели как ошибка через role=tool с правильным tool_call_id;
- после ошибки цикл продолжился и получил финальный ответ;
- при max_steps=1 цикл остановился с error=max_steps.

В проверках используется подставной клиент.
OpenAI, Qdrant и Telegram не вызываются.

Команда:

python -m app.services.agent_naive --help

CLI показывает аргумент task и параметры --max-steps, --trace.

## Соответствие заданию и ограничения

- Выполнено более пяти формулировок из предметной области.
- Есть успешный сценарий поиска и отправки за 3 шага.
- Выполнены сценарии отсутствия данных, недоступного инструмента,
  длинной задачи и срочной отправки.
- Проверены обработка неизвестного вызова и ограничение шагов.
- Неудачные прогоны сохранены.
- Используются явный DISPATCH и три инструмента с JSON Schema.
- Telegram представлен только заглушкой.
- Агентный цикл не использует внешние агентные библиотеки.
  Инструмент поиска использует зависимости существующего RAG проекта.

При проверке после переноса промпта agent_naive.py содержал 80 строк.
Цикл вместе с трассировкой и проверками занимал 43 строки,
что превышает ориентир «чистая логика около 25 строк».
Описания инструментов и промпт находятся в отдельных модулях.

Оставшиеся ограничения:
- Ошибочное сопоставление по общей теме «списание» не подтверждено как исправленное.
- При повторном поиске агент может добавлять неуказанные симптомы.
- В длинном прогоне нарушен формат ответа без совпадений:
  фраза помещена под заголовок «Релевантные баги».
- Подтверждение отправки программно не контролируется.
- После перехода к полной карточке повторно проверен только успешный сценарий поиска и отправки.
- Возврат полной карточки отличается от буквального требования исходного задания о возврате одного фрагмента.

Итог: Обязательные функциональные сценарии наивного агента выполнены.
Неудачные результаты сохранены и разобраны. Ориентир по компактности соблюдён для основного файла — 80 строк.
Цикл с проверками и трассировкой занимает 43 строки вместо ориентира около 25. В 43 строки вошли:
- вызов модели и обработка инструментов;
- обработка ошибок инструментов;
- сбор и запись trace;
- проверка пустого ответа;
- проверка ответа об отсутствии багов без поиска. Чтобы приблизиться к референсу, нужно вынести обработку инструментов, трассировку и проверку финального ответа в отдельные функции. Поведение и защиты сохранятся; структура остаётся одним циклом вокруг одного вызова Chat Completions.

Ошибки смыслового сопоставления остаются ограничением реализации.
Их наличие не скрывается и не означает, что все прогоны успешны.
